# DZ1 Java — Каталог автомобилей (Резяпова Р.И. РИМ-160980к, УРФУ)

Консольное Java-приложение для управления коллекцией автомобилей. Поддерживает добавление данных вручную и импорт из JSON-файлов, фильтрацию и сортировку записей.

## Функционал

- **Добавление автомобилей вручную** — ввод марки, мощности двигателя и года выпуска с проверкой корректности данных и подтверждением добавления.
- **Импорт из JSON** — загрузка списка автомобилей из файлов в `src/main/resources/json/`. Некорректные записи отбрасываются, перед добавлением можно просмотреть результат и подтвердить операцию.
- **Просмотр каталога** — вывод всех добавленных автомобилей.
- **Фильтрация**:
  - по названию модели или его части;
  - по минимальной мощности двигателя;
  - по году выпуска.
- **Сортировка**:
  - по названию модели;
  - по мощности двигателя;
  - по году выпуска;
  - по возрастанию и убыванию.
- **Выбор алгоритма сортировки** — пузырьковая сортировка (*Bubble Sort*) или сортировка вставками (*Insertion Sort*).

## Запуск и тестирование

Откройте проект в IntelliJ IDEA и запустите класс `Main`.

## 1. Добавить данные вручную
- Марка автомобиля не должна быть пустой, допускается ввод любых строковых значение, символов, цифр.
- Мощность двигателя должна быть конечным числом больше нуля. Допускается введение дробного числа через запятую (например: `150,0`), так как перед валидацией программа автоматически заменяет любые запятые на точки. Значения `NaN` и `Infinity` являются невалидными.
- Год выпуска должен находиться в диапазоне от 1900 года до текущего года. Текущий год определяется программой динамически через java.time.Year, что исключает возможность добавления машины с годом из будущего.

Данный пункт меню зациклен, допускается множественный ввод объектов до тех пор, пока пользователь не откажется от продолжения.

## 2. Добавить данные из файла
Для добавления объектов класса Car в папке resources/json предусмотрено несколько тестовых файлов:
- `car.json`. Содержит 3 валидных экземпляра класса, которые успешно пройдут валидацию, а также null. Программа корректно обрабатывает этот случай и безопасно игнорирует null-строку, не прерывая чтение остальных данных.
- `test.json`. Содержит 1 валидный экземпляр класса и 4 невалидных: валидация не пропустит отрицательную мощность (-50.0), год выпуска, выходящий из валидного диапазона (2090000 и 2027), пустую строку в модели. Имеется вывод в консоль общего предупреждения о том, что объект не прошел проверку.
- `uncorrect.json` - содержит JSON-файл с намеренной ошибкой (опечатка в названии поля: modell вместо model). Программа ловит исключение, выводит в консоль причину ошибки и продолжает работу без аварийного завершения.
- `uncorrectInt.json` - содержит значение, вызывающее переполнение типа int в поле года. Программа ловит исключение, выводит в консоль причину ошибки и продолжает работу без аварийного завершения.
- `unknown.json` - тест на обработку несуществующего файла. Программа выводит в консоль сообщение о том, что файл не найден без аварийного завершения.

Данный пункт меню зациклен, допускается множественный ввод объектов до тех пор, пока пользователь не откажется от продолжения.

## 3. Фильтрация данных
Проверки для данного пункта написаны с учетом добавления экзмепляров класса из файлов car.json. и test.json из предыдущего шага:
- По названию модели. Программа выполняет фильтрацию по названию модели без учета регистра.
При вводе значений `bm` или `bmw` программа выведет 2 совпадения. При вводе значения `opel` программа выведет сообщение об отсуствии найденных совпадений. Ввод пустой строки отменит поиск и вернет пользователя в меню.
- По мощности. Программа выполняет фильтрацию начиная с минимальной мощности. Допускается введение дробного числа через запятую (например: `150,0`).
При вводе значения `150` программа выведет 4 совпадения, `250` - 2 совпадения, `300` - 0 совпадений. Значения `-150`, `число`, `NaN` и `Infinity` являются невалидными.
- По году выпуска. Программа выполняет точный поиск по году выпуска.
При вводе значения `2010` программа выведет 1 совпадение, `2026` - 0 совпадений. Значения, не являющиеся целыми числами (например, текст или дробные числа), считаются невалидными.

## 4. Сортировка данных
Проверки для данного пункта написаны с учетом добавления экзмепляров класса из файлов car.json. и test.json из предыдущего шага:. Программа позволяет выбрать один из двух алгоритмов сортировки: «пузырьком» или «вставками» (выбор алгоритма не влияет на итоговый результат, меняется только внутренняя логика). После выбора алгоритма предлагается указать критерий сортировки (например, модель, мощность или год выпуска) и её направление (по возрастанию или по убыванию):
- По названию модели и по возрастанию: программа сортирует объекты в лексикографическом порядке (по алфавиту) на основе поля model. Ожидаемый результат:

BMW X5 — 250.0 л.с., 2020 г.
Lada — 150.0 л.с., 2023 г.

## 5. Вывести список данных на консоль
Программа выводит список всех добавленных экземпляров класса Car в консоль в том порядке, в котором они были добавлены (порядок загрузки из файла или ручного ввода). Метод не выполняет дополнительную фильтрацию или сортировку. Если список пуст, программа выводит соответствующее уведомление.
